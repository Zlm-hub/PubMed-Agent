# 监控日志设计方案（后端全链路）

> 状态：**已实施（2026-09-18 晚，D1–D5 全部按建议落地）**——实测：request_id 贯穿 request.start → rewrite → esearch/efetch → stats → litlog → request.done 全链 8 条日志；/api/logs?tail=100 可在线查看；uvicorn access 降噪生效；error.log 就位。
> 原则：标准库 logging 零新依赖、自包含新模块、默认配置下行为不变、绝不因日志问题影响主链路

---

## 0. 现状盘点：排查今天为什么难

| 窟窿 | 位置 | 后果 |
|---|---|---|
| **全后端零文件日志** | 只有 uvicorn 控制台 access log | 重启后历史全丢；用户终端里混在启动信息里 |
| **异常静默吞掉**（5 处） | `metrics.learn`、`query_translate`（L0 查表/LLM/试搜全链）、`literaturedb.save_alias` | 改写为什么没生效、别名为什么没学到——完全无迹可查 |
| **落库失败只有一条 trace** | pipeline litlog | trace 随响应返回但**不持久化**，下次请求看不到 |
| **502 只有 message 没有堆栈** | main.py except | "分析流水线失败: xxx" 一行字，根因（哪一步、什么参数）丢失 |
| **trace 是易失的** | 每次响应体里 | 无法回答"昨天那次检索为什么慢/为什么 0 命中" |

## 1. 目标

1. **每一步可回放**：请求 → 改写 → esearch → efetch → 指标匹配 → 聚合 → 综述 → 落库 → 响应，每步一条结构化日志（成功/失败/耗时/关键参数）
2. **错误可定位**：异常带完整堆栈落文件；一次请求的所有日志用 `request_id` 串起来——客户/前端报问题时报这一个码即可
3. **零新依赖**：标准库 `logging` + `TimedRotatingFileHandler`
4. **绝不影响主链路**：日志调用全部 best-effort，日志器自身故障也不抛

## 2. 日志形态

### 2.1 落盘（`backend/logs/`，加入 .gitignore）

| 文件 | 内容 | 轮转 |
|---|---|---|
| `app-YYYYMMDD.log` | INFO+，按天轮转，保留 14 天 | 每行：`时间 \| 级别 \| request_id \| 模块 \| 事件 \| 详情JSON` |
| `error-YYYYMMDD.log` | ERROR+，含完整堆栈，保留 30 天 | 同上 |

### 2.2 一次请求的日志样例（request_id 贯穿）

```
2026-09-18 22:40:01 | INFO  | a3f2c1 | pipeline  | request.start  | {"query":"渐冻症","retmax":200,"review":true}
2026-09-18 22:40:01 | INFO  | a3f2c1 | rewrite   | mapping.hit    | {"raw":"渐冻症","term":"amyotrophic lateral sclerosis","ms":105}
2026-09-18 22:40:05 | INFO  | a3f2c1 | pubmed    | esearch.done   | {"term":"...sclerosis","total":41712,"ms":4365}
2026-09-18 22:40:06 | INFO  | a3f2c1 | pubmed    | efetch.done    | {"batches":2,"parsed":200,"ms":980}
2026-09-18 22:40:06 | INFO  | a3f2c1 | metrics   | enrich.done    | {"known":132,"unknown":68,"sample_unknown":["Deutsche medizinische..."]}
2026-09-18 22:40:06 | INFO  | a3f2c1 | pipeline  | litlog.done    | {"query_id":9,"articles":200,"ms":108}
2026-09-18 22:40:06 | INFO  | a3f2c1 | pipeline  | request.done   | {"total":41712,"elapsed_ms":5120,"cached":false}
2026-09-18 22:40:06 | ERROR | a3f2c1 | review    | llm.failed     | {"error":"timeout"} + 堆栈
```

### 2.3 request_id 机制

- 入口生成 6 位短码（时间戳+随机），写入响应体 `request_id` 字段
- 用标准库 `contextvars.ContextVar` 透传——**pubmed / review / query_translate 的函数签名一行不改**，日志器自动带上
- 前端暂不展示（可选后续在错误提示里带上）

## 4. 明确不做（本期边界）

- 不做前端日志面板（`/api/logs` 查看接口作为可选项，见 D2）

## 7. v2 升级：认证审计 + 请求访问日志（2026-09-21 实装）

**触发**：用户反馈「报错都没有记录」——闸门 401 只在 uvicorn 控制台一闪而过，app.log 无痕；登录/退出也没有任何记录。

**新增事件**（全部沿用 monitor 现有双文件通道，格式不变 `时间 | 级别 | rid | 模块.事件 | JSON`）：

| 事件 | 级别 | 字段 | 触发时机 |
|---|---|---|---|
| `auth.gate.denied` | WARNING | path/method/client/has_session_cookie/has_code_header/mode/ms | 受保护 /api/* 请求未通过闸门（未登录/token 失效/无凭证） |
| `auth.login.ok` | INFO | user/role/client/ua | 登录成功（口令模式记 user="(口令模式)"） |
| `auth.login.failed` | WARNING | user/client/ua | 用户名或密码不正确（连续失败=撞库信号） |
| `auth.code.failed` | WARNING | client/ua | 旧口令校验失败 |
| `auth.register.ok` / `auth.register.failed` | INFO / WARNING | user/role/bootstrap/client | 注册成功 / 被拒（用户名重复等） |
| `auth.logout` | INFO | user/client | 退出登录（按 cookie 解出是谁） |
| `api.access` | INFO | method/path/status/user/client/ms | 除 health、analyze、stream 外的每个 /api/* 请求（analyze 有更细的 request.start/done，不重复记） |
| `api.unhandled.error` | ERROR（带堆栈） | path/method/error | 全局异常兜底：FastAPI 默认只打控制台，现统一落 error.log，响应体带 request_id |

**实现位置**：`backend/app/main.py`（闸门中间件 + 登录/注册/登出路由 + `@app.exception_handler(Exception)`）；monitor.py 零改动。

**同日配套的前端修复（401 根因，不是日志问题但一起修了）**：本地 5173→8000 跨端口 fetch 未带 `credentials:"include"`，浏览器既不发 cookie 也丢弃响应的 Set-Cookie → 登录"成功"后所有请求 401。修复 = vite dev 加 /api 代理同源化（vite.config.ts）+ 全部 fetch 补 credentials + EventSource withCredentials + 后端 CORS `allow_credentials=True`。

**验收**：TestClient 七场景（401/注册/登录失败/登录成功/带身份访问/登出/登出后再访问）全部按预期落 app.log；回归 83 项（isolation 26 + http_auth 41 + register 16）全绿。
