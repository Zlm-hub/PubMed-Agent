# 升级设计方案：数据层 v2 与中文检索

> 状态：**已实施（2026-09-18，D1–D7 全部按建议落地）**——实测：渐冻症→映射改写(105ms)→ALS 命中 41,712 篇；长尾「肠漏综合征」→LLM 改写→命中 34,316 篇；自学习别名 184 个；0 命中不落文件缓存的修复同步完成。
> 原则：新增模块自包含、不动现有对话外壳与报告链路、全部改动带开关可回退

---

## 0. 背景与目标

客户反馈聚焦三点，本方案逐一对应：

| 客户痛点 | 实测证据 | 本方案对应 |
|---|---|---|
| 中文搜不了 | 「渐冻症」esearch 命中 0 篇 | 第 2 节：中文查询改写 |
| 数据不可积累 | 每次实时打 NCBI，历史查不到 | 第 1 节：literature.db 文献落库 |
| 指标口径存疑 | 篇均被引 ≠ 官方 IF；缩写刊匹配不上 | 第 3 节：指标库扩展 + 口径正名 |

## 1. 数据库设计（DDL 级）

### 1.1 双库分工（决策点 D1）

| 库 | 读写模式 | 生命周期 | 理由 |
|---|---|---|---|
| `journal_metrics.db`（已有） | **只读**，随包发布 | 年级更新 | 指标重建/重发不伤文献数据 |
| `literature.db`（新建） | 运行时读写、持续增长 | 随使用增长 | "可再生的"与"不可再生的"分离 |

### 1.2 literature.db 完整 DDL

```sql
-- 版本管理：后续 schema 变更走这里记录
CREATE TABLE IF NOT EXISTS schema_meta (
    key   TEXT PRIMARY KEY,
    value TEXT
);

-- 检索词字典：term_raw=用户原话，term=实际检索词；改写缓存就在这张表
CREATE TABLE IF NOT EXISTS search_query (
    id             INTEGER PRIMARY KEY,
    term_raw       TEXT NOT NULL,
    term           TEXT NOT NULL,
    retmax         INTEGER NOT NULL DEFAULT 200,
    rewrite_source TEXT,              -- 'passthrough' | 'mapping' | 'llm'
    last_total     INTEGER,           -- 最近一次命中数（0 命中信号）
    first_seen_at  TEXT NOT NULL,
    last_run_at    TEXT NOT NULL,
    UNIQUE (term_raw, retmax)
);

-- 文献主表：摘要存全量（决策点 D2），综述生成不再依赖 efetch
CREATE TABLE IF NOT EXISTS article (
    pmid         INTEGER PRIMARY KEY,
    title        TEXT,
    norm_journal TEXT,                -- 归一化刊名（冗余，跨库关联靠它+issn）
    issn         TEXT,                -- 主 ISSN（冗余）
    year         INTEGER,
    abstract     TEXT,
    pub_types    TEXT,
    fetched_at   TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS ix_article_journal ON article(norm_journal);
CREATE INDEX IF NOT EXISTS ix_article_year ON article(year);

-- MeSH 标注拆表：研究方向聚合一条 GROUP BY 搞定
CREATE TABLE IF NOT EXISTS article_mesh (
    pmid      INTEGER NOT NULL REFERENCES article(pmid) ON DELETE CASCADE,
    mesh_term TEXT NOT NULL,
    PRIMARY KEY (pmid, mesh_term)
);

-- 命中集：哪次检索命中哪些文献，带排名（命中集可复现）
CREATE TABLE IF NOT EXISTS search_hit (
    query_id INTEGER NOT NULL REFERENCES search_query(id) ON DELETE CASCADE,
    pmid     INTEGER NOT NULL REFERENCES article(pmid) ON DELETE CASCADE,
    rank     INTEGER NOT NULL,
    PRIMARY KEY (query_id, pmid)
);
CREATE INDEX IF NOT EXISTS ix_hit_pmid ON search_hit(pmid);

-- 分析快照：报告页秒开 + 历史回放；代码口径升级后可按 query_id 重算
CREATE TABLE IF NOT EXISTS analysis_run (
    id          INTEGER PRIMARY KEY,
    query_id    INTEGER NOT NULL REFERENCES search_query(id),
    params_json TEXT NOT NULL,
    stats_json  TEXT NOT NULL,        -- 含 Top100
    review_text TEXT,                 -- 综述独立成列（决策点 D3）
    review_mock INTEGER NOT NULL DEFAULT 0,
    elapsed_ms  INTEGER,
    created_at  TEXT NOT NULL
);

-- 中文→英文术语映射表（L0，见 2.2）：status 两态，candidate 不过护栏不入正式
CREATE TABLE IF NOT EXISTS term_mapping (
    term_cn     TEXT PRIMARY KEY,
    term_en     TEXT NOT NULL,
    synonyms    TEXT,                 -- JSON 数组，可空
    source      TEXT NOT NULL,        -- 'seed'（交付预置）| 'llm-reflow'（运行回流）
    verified_at TEXT,
    status      TEXT NOT NULL DEFAULT 'candidate'  -- candidate | approved
);
```

### 1.4 跨库关联规则

SQLite 跨库无外键。约定：`article` 冗余存 `norm_journal + issn`，**匹配逻辑放代码层**（沿用现有 `metrics.enrich` 的两级字典），两库各自独立可迁移。

## 2. 中文查询改写（三层兜底链）

### 2.1 总体链路

```
用户输入（含中文）
  │
  ├─ L0 查 term_mapping（status=approved）── 命中 → 0ms 直接用
  │
  ├─ L1 LLM 改写（长尾词）── JSON 结构化输出 → 自动校验 → 通过则落库
  │        └─ 校验：回译比对 + esearch 试搜命中数 > 阈值
  │
  └─ L2 仍 0 命中 → 响应带 suggestions 字段 → 前端弹英文候选 chips
```

- **触发条件**：输入含 CJK 字符才走改写，纯英文直通（决策点 D4）
- **缓存**：改写结果写入 `search_query`（`rewrite_source` 记来源），同词永不再翻
- **透明性**：工具卡沿用现有 `raw_input` 机制，如实展示「你输入的」与「实际检索的」

### 2.2 LLM 改写协议

- Prompt 要点：把「中文问题」改写为 **PubMed 检索式**（核心术语 2~4 词，可含同义词），禁止输出整句；优先 MeSH 规范名；不确定时 confidence < 0.6
- 输出 JSON：`{"term": "...", "synonyms": ["..."], "confidence": 0.9}`
- temperature=0.2；模型沿用现有 DashScope qwen 配置
- `confidence < 0.6` 或 esearch 试搜命中数异常（0 或 >100 万）→ 不落 approved，走 L2

### 2.3 术语表审核流程（交付时一次，客户零参与）

| 阶段 | 谁 | 动作 |
|---|---|---|
| 起草 | LLM | 生成 50~100 条高频中文医学术语候选 |
| 自动校验 | 脚本 | 回译比对（英→中对照原词）+ esearch 试搜命中数信号，全程中文语境可判断 |
| 固化 | 我们 | 扫一眼存疑条目 → approved 入表，随产品交付 |
| 回流 | 程序 | 运行期 L1 改写成功且命中的词，自动以 candidate 入表，审核后升级 approved |
